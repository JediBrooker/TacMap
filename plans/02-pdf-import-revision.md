# PDF import revision (GeoPDF + fiduciary calibration), iOS + Android

Status: in progress on `review/pdf-sync-threat-model`. Source audit: 6 specialist
auditors + skeptic verification (2026-09-30), ~80 confirmed findings (ids D1-xx ..
D6-xx referenced below).

## Acceptance criteria

1. Every GeoPDF from a real producer that GDAL can georeference, TacMap places
   correctly on both platforms (USGS US Topo, Esri ArcGIS export, TerraGo/LGIDict,
   ISO 32000 with PROJCS/GEOGCS/EPSG). A declared-but-unreadable georeference is a
   loud, explained failure that offers manual calibration, never a silent
   camera-centred box.
2. The MGRS grid overlay sits on the printed UTM grid of a UTM-projected sheet to
   within 1 screen pixel (and <= 1 m on the ground) at every zoom from sheet-fit to
   max, for GeoPDFs and for fiduciary-calibrated plain PDFs, anywhere on the sheet,
   including rotated (skewed scan) sheets.
3. Zooming in stays crisp (vector PDF content rendered at display density, no 72 dpi
   blur), zooming out never blanks the map or snaps the camera, and there are no
   black holes / flashes between zoom levels or at tile seams.
4. Fiduciary calibration works on both platforms with full pan/zoom, precise
   crosshair placement, flexible coordinate entry, visible fit quality with
   per-point residuals, and edit/delete/undo. It survives app kill.
5. Import never silently deletes a user's other maps; destructive actions confirm.
6. iOS and Android produce the same georeference for the same file, pinned by shared
   fixtures in `testdata/` generated by an independent third implementation (PROJ via
   pyproj).

## 1. Georeference model (shared contract)

Replace "one affine from page points to WGS84 lon/lat" with a projection-space model:

```
PdfGeoreference {
  page:      Int                 // 0-based page index the georef applies to
  crs:       GeoCrs              // plane the affine maps into
  datum:     GeoDatum            // ellipsoid + 3-param geocentric shift to WGS84
  affine:    [a,b,c,d,e,f]       // page user space -> plane: X = a*x + b*y + c ; Y = d*x + e*y + f
  crop:      [[x,y]...]          // page-space polygon to show (neatline / viewport), >= 3 pts
  origin:    adobeVP | lgiDict | fiduciaries | provisional
  fit:       { rmsMetres, maxResidualMetres, perPoint:[metres], crossValidated }  (optional)
}
GeoCrs = geographic                                   // plane = (lon, lat) degrees in `datum`
       | transverseMercator(lat0, lon0, k0, fe, fn)   // UTM zone z = TM(0, 6z-183, 0.9996, 500000, 0|10000000)
       | lambertConformalConic2SP(lat1, lat2, lat0, lon0, fe, fn)
       | lambertConformalConic1SP(lat0, lon0, k0, fe, fn)
       | mercator1SP(lon0, k0, fe, fn)                // also covers 2SP via k0 = cos-scale of lat_ts
```

- Page space is the PDF default user space of the page: raw coordinates, y up,
  INCLUDING any MediaBox/CropBox origin offset and IGNORING /Rotate. Every parser
  produces page points in this space and every renderer maps from it explicitly.
  /Rotate and box origins are applied only by the renderer's own page->pixel matrix
  (D1-04, D1-05, D3-05, D3-06, D4-15, D6-10, D5-12). Rotated pages are supported, not
  rejected.
- `toWGS84(page) = datum.toWGS84( crs.inverse( affine(page) ) )`
- `toPage(wgs84) = affine^-1( crs.forward( datum.fromWGS84(wgs84) ) )`
  (`fromWGS84` = the same 3-parameter geocentric shift with negated translation.)
- Forward AND inverse must exist on both platforms for TM (Snyder/Krueger series,
  <1 mm inside +-4 deg of CM), LCC 1SP/2SP, Mercator, and geographic. Tolerances vs
  pyproj: 1 mm in plane metres, 1e-9 deg.
- Datums: WGS84, NAD83, GDA94, GDA2020, ETRS89 (identity or published 7-param where
  already implemented), NAD27, ED50, OSGB36, Tokyo, CH1903, NTF, SK-42 (existing
  3-param tables; iOS `DatumShift` and Android `LgiDatum` must share one table, pinned
  by fixture).

### Construction

- ISO 32000 / Adobe `/VP` (page, then catalog): choose the GEO viewport with the
  largest BBox area among those that yield a valid georef. LPTS are mapped linearly
  against the BBox endpoints exactly as written (BBox may be reversed in y). Accept any
  finite LPTS in [-0.5, 1.5]; reject outside (D1-01). GPTS are (lat, lon) in the GCS's
  geographic datum. Parse `/GCS`: `/WKT` PROJCS (TM/UTM, LCC 1SP/2SP, Mercator) or
  GEOGCS; or `/EPSG` (326zz/327zz WGS84 UTM, 269zz NAD83 UTM, 267zz NAD27 UTM,
  283zz GDA94 MGA, 78zz GDA2020 MGA, 4326/4269/4283/7844 geographic). Datum from the
  WKT DATUM name (ESRI `D_...` and OGC names) or TOWGS84. Project the GPTS into the
  plane (forward, source ellipsoid) and least-squares fit the affine page->plane.
  Crop = the viewport BBox rectangle (or /Bounds polygon if present). Unsupported
  projection: fall back to a local TM centred on the GPTS centroid (document it; still
  far better than a lat/lon affine). Gate: plane RMS <= max(2 m, 0.002 * sheet
  diagonal in metres) else reject as malformed (D1-02, D1-03).
- OGC LGIDict: CTM or Registration give page->plane pairs directly; fit the affine in
  plane units, no per-point inverse. Accept real-world codes (`LE` = LCC,
  `NAS-C`/`NAS-E`/`NAR-C`/`WGE`/`WE`, etc., D1-06). Entry selection and CTM vs
  Registration precedence must be identical on both platforms: prefer /CTM when both
  are present and agree within 1 m, else Registration; take the entry named Layers,
  else the largest neatline (D1-07). Neatline -> crop.
- Fiduciaries: each point = page point + the user's typed reference + sheet datum.
  Convert every reference to geodetic (sheet datum). Plane = UTM zone of the FIRST
  point (MGRS/UTM input gives it directly; lat/lon input -> standard zone), hemisphere
  of the first point; forward all points into that one zone (valid across a zone
  boundary). Least-squares affine page->plane; per-point residuals in metres; RMS;
  crossValidated = n >= 4. Degeneracy: reject if the eigenvalue ratio of the page-space
  point covariance < 0.02 (collinear/clustered, D2-10), warn when points span < 25% of
  the crop in either axis.
- Provisional (plain PDF during calibration only): geographic WGS84, page centred on
  the camera, north-up, nominal 1:50,000. Never presented as a usable basemap: always
  with an "uncalibrated" banner (D2-06, D5-02).

### Persistence and migration

The sealed session/library JSON gains `georef` (version 2). Loading a v1 entry:
- GeoPDF source: re-parse the PDF (content-hash keyed) to get the v2 georef.
- Fiduciary source: refit from the stored fiduciaries (their stored lat/lon are WGS84)
  in the UTM zone of the first point.
- Legacy camera-fallback entries (calibratedPDF with no fiduciaries): mark
  uncalibrated and ask the user to calibrate instead of showing a made-up placement.

## 2. Rendering and zoom (one tile renderer for live view and bake)

- The PDF is shown through a raster tile source (the same seam as MBTiles/online
  tiles) that renders Web Mercator tiles on demand from the page:
  for each output cell, compute the page points of the cell corners with `toPage`,
  build the affine page->cell-pixels from three corners, measure the error at the 4th
  corner and the centre, and split into 4 while error > 0.25 px (max depth 4). Clip
  to the cell and to the crop polygon, set the CTM, draw the page. Off-sheet pixels are
  transparent (D3-01, D2-04, D4-09, D3-03, D4-02 display half, D3-12, D1-08).
- Resolution: tiles are rendered at the display density (256 pt tiles at
  `min(screenScale, 3) * 256` px, or 512 px tiles at z-1 where cheaper) so vector
  linework and text stay crisp (D3-04, D4-14, D2-14). Low zooms whose required
  resolution is below the cached whole-page base raster sample that raster with the
  same cell warp (fast), otherwise render the vector page.
- Zoom policy: no hard pinch clamp to the PDF's range (D3-08). The source reports
  `detailZoom` = zoom where one tile pixel ~= 1/4 PDF point on the ground (vector PDFs
  stay crisp to here); beyond it tiles are overzoomed from detailZoom. The camera's
  global max applies. minZoom 0 (base-raster tiles).
- Tile view: parent (and child) tile fallback while tiles load, for every raster
  source, so zoom changes and pans never show holes (D3-11). Decode/render off the main
  thread (D3-13, D5-08). Memory LRU cache sized to the device; no new plaintext disk
  cache of rendered tiles.
- Bake ("Generate offline tiles") reuses the exact same tile render function, writes
  .partial then publishes, keeps the source PDF (D5-05), is cancellable with progress,
  survives sheet dismissal / configuration change (D3-07, D3-10, D5-06), uses
  completeUntilFirstUserAuthentication on iOS (not .complete), and caps zoom at
  detailZoom with a size estimate confirm.
- Visibility toggles for the imported map work (D3-14, D5-17). Render failures are
  surfaced, not a blank map under a green label (D5-16).
- Crash-loop breaker: mark "first render pending" before the first render of a new
  import; if the app dies before it completes, the next launch does not auto-render
  that map and tells the user (D5-07).

## 3. MGRS grid overlay

Both platforms (D4-04..D4-13, D6-02, D6-06, verifier notes):
- Label = the line's own value (fix northern-hemisphere off-by-one, 10 km easting
  west of CM, 100 km labels).
- Densify every line so max chord sagitta <= 0.25 px at the current zoom (100 km and
  10 km lines are curves in Web Mercator).
- Clip every segment to its own zone's longitude span (and band latitude span), no
  neighbour-zone intrusion, no first-column diagonals from NGA GridZone, no duplicate
  segments at band boundaries.
- Level of detail chosen in density-independent units (dp/pt) with the same
  thresholds on both platforms; hide a level whose spacing is < ~40 dp (including
  100 km lines when zoomed far out); rebuild off the main thread, cache by
  (zone set, precision, quantised viewport) with a margin larger than the rebuild
  fingerprint step so panning never shows missing lines.
- Labels placed inside the visible viewport edges (declutter against the visible
  rect, not the coverage square).
- Pinned by `testdata/mgrs_grid.json`.

## 4. Calibration UX (both platforms, same flow)

- Entry: automatically after importing a PDF with no georef; from Layers
  ("Calibrate / refine georeference") for any PDF including GeoPDFs.
- Map pan/zoom/rotate stay live during calibration (D2-01). Placement is by the
  screen-centre crosshair with an explicit "Add point" button (no tap-vs-drag
  ambiguity); the page point is `georef.toPage(crosshair)` through the same georef
  that renders the tiles (exact at any zoom/rotation, D2-02, D4-07, D6-03).
  Starting calibration ends measure/draw modes (verifier note on Android pointer
  input).
- Coordinate entry accepts: full MGRS (any spacing/case, 4-10 digits), MGRS
  shorthand (digits only, or 100 km square + digits) completed from the previous
  point's GZD/square, UTM (`55H 691000 6089000`), lat/lon DD and DMS. Reuse the
  offline coordinate parser from Search. Reject 0/2-digit MGRS (100 km / 10 km) as too
  coarse. Show the parsed interpretation before accepting. Sheet datum picker (once
  per calibration) with the full datum list (D2-05, D2-11, D2-12).
- Live refit after 3+ points: the page re-renders at the new georef and the camera
  keeps the same page point under the crosshair. Fit panel: n points, RMS, max
  residual, per-point residuals; 3 points says "exact fit - add a 4th point to check
  accuracy"; outliers flagged (D2-07).
- Point list: select a point to move (re-place at crosshair), edit its coordinate, or
  delete; undo last action; pending markers drawn at the page points on the sheet
  (D2-08, D2-13).
- Finish requires a valid non-degenerate fit and shows a clear reason otherwise
  (D2-09, D5-11). Cancel with changes asks to discard.
- In-progress calibration is persisted (sealed) and tied to the PDF content key; it
  can never be applied to a different PDF (D5-10).

## 5. Import lifecycle and hardening

- Library: imported maps persist until the user deletes them; Layers lists them with
  switch and delete (confirm) (D5-03, D5-04). Deleting a map removes its files, baked
  tiles and calibration (D5-19).
- Multi-page PDFs: use the first page carrying a valid georef; if none and >1 page,
  let the user choose the page (D5-13).
- Progress + cancel for import parsing; parse the untrusted PDF once; no main-thread
  hashing/raster (D5-08, D5-09).
- Budgets: file size, page count, page box size, raster memory, parse time; Android
  must not swallow OutOfMemoryError/StackOverflowError into "success" (D5-15).
- iOS: imported maps excluded from backup (isExcludedFromBackup), stored under
  opaque names (D5-14). Android: do not persist the picked document URI/name in
  plaintext prefs (D5-18).
- Same limits and user-facing messages on both platforms (D5-20).
- THREAT_MODEL.md: document imported-map at-rest status and untrusted-PDF parsing.

  unit-test suites; expected values from pyproj/PROJ.
- USGS sample: pinned by its extracted /VP dictionaries in the fixture (the 38 MB PDF
  stays out of git); tests that open the real file skip when it is absent.
- On-device: import each synthetic sheet (+ USGS) on iOS simulator and Android

  printed-grid vs overlay offset with `scripts/grid_alignment.py` (<= 1 px / 1 m).
  Zoom sweeps min->max->min; pan across tile seams; rotate device; switch basemap and
  back; kill and relaunch; delete.
