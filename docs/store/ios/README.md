# App Store screenshots

> Listing copy (title, subtitle, promo text, description, keywords) lives in
> [`docs/STORE_LISTING.md`](../../STORE_LISTING.md).

Captured from the real app on the iOS Simulator at **Shoalwater Bay Training
Area, QLD**, via the `TacticalMapsUITests` screenshot UI test (see
`ios/TacticalMapsUITests/ScreenshotTests.swift`). There is no standalone
`ios_screenshots.sh`; run the UI test against the one existing release-test
simulator and extract attachments from its `.xcresult` with
`xcrun xcresulttool export attachments`. The default marketing capture uses a
deterministic offline Unit Sync disclosure and never needs a relay room. A live
Sync capture must be given a fresh, run-scoped v3 join code through
`TACMAP_SCREENSHOT_ROOM_CODE`; the test skips connected-only captures when that
value is absent and does not contain a reusable production room.

Choose and reuse one existing simulator; do not create a screenshot-specific
clone:

```sh
cd ios
export IOS_SIMULATOR_UDID='<existing-iPhone-simulator-UDID>'
xcodegen generate
xcodebuild test \
  -project TacticalMaps.xcodeproj \
  -scheme TacticalMaps \
  -destination "platform=iOS Simulator,id=$IOS_SIMULATOR_UDID" \
  -only-testing:TacticalMapsUITests/ScreenshotTests/testCaptureMarketing \
  -resultBundlePath build/screenshots/TacticalMaps.xcresult
```

For a deliberately connected capture, prefix that command with
`TACMAP_SCREENSHOT_ROOM_CODE='<fresh-v3-code-for-this-run>'`. Retire the code
after capture; never commit it to the test or this document.

## 2.2 set: 8 slides, same order and text on every device

Captured from the real app on the simulator (iPhone 17 Pro Max, iPad Pro 13-inch
(M5)) with the `testStore*` tests in `ScreenshotTests.swift`, then framed by
`scripts/compose_store_set.py` (text and order live in its `SPEC`). The shared
situation is `docs/store/store_situation.geojson` (Blue Mountains, NSW), imported
through the app's own GeoJSON import. Unit Sync slides used a fresh throwaway v3
room with two simulators; the join code is never on screen.

1. `01-hero.png` — the shared NATO situation with range rings on the enemy position
2. `02-line-of-sight.png` — elevation profile and line of sight (real Copernicus DEM heights)
3. `03-night-mode.png` — the same map with red night mode on
4. `04-unit-sync.png` — Unit Sync connected with a second live unit (iOS) / TacMap Chat in a live room (Android)
5. `05-sun-moon.png` — Sun & Moon sheet from the long-press point menu
6. `06-pdfmap.png` — imported USGS GeoPDF with Search & Rescue markers
7. `07-symbol-builder.png` — APP-6 symbol builder with live preview
8. `08-export.png` — Import / Export with KML, KMZ with Symbols, GeoJSON and GPX

## Notes
- Generated by the `TacticalMapsUITests` UI-test target (added to
  `ios/project.yml`). Location is set at the device level by
  `xcrun simctl location set` so the basemap shows Shoalwater Bay.
- Compare every caption with the candidate build before upload. In particular,
  online maps/weather/places require their explicit OPSEC gates, Unit Sync
  member liveness is relay-reported, and recorded tracks export separately from
  **Export All Mission Objects** GeoJSON.
- Reject any screenshot that says the relay “only ever sees ciphertext.” The
  current disclosure must say that mission payloads and TacMap Chat are E2E
  encrypted while routing, session, and traffic metadata remain visible.
- Import/export captures must say **Export All Mission Objects**; recording and
  search captures must visibly show the **REC** indicator and **Search** sheet.
- Any connected Unit Sync capture must show the TacMap Chat shortcut.
